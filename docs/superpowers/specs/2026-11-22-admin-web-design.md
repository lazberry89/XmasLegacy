# 관리자 웹 대시보드 설계

## 목적
운영자가 게임 DB(`xmas_legacy`)를 MySQL 콘솔 없이 브라우저에서 읽기 쉽게 보는 것.
관리자 전용이며, 키 하나만 입력하면 바로 들어간다.

## 목표 / 비목표 / 실패 조건
- 목표: 유저·문의·가방·우편함·후원지급·업적을 탭별로 보기 좋게 표시한다. 디자인은 xmaslegacy.xyz 컨셉(마크 타이틀 화면, 밤하늘, 눈, 픽셀 폰트)을 따른다.
- 비목표: 데이터 수정(답변 작성, 돈 변경 등), 플레이어용 화면, 외부 공개 설정(포트포워딩은 사용자가 나중에 직접).
- 실패 조건: 키 없이 데이터가 보이거나, 키가 리포지토리에 커밋되거나, 대시보드가 DB에 쓰기를 하는 것.

## 제약
- 게임 DB는 집 서버(192.168.45.51) 로컬 MySQL `xmas_legacy`. 외부에 열려 있지 않다.
- Velocity 플러그인(`velocity` 모듈, Java 21)은 이미 이 DB의 접속 정보를 `plugins/xmaslegacy-velocity/config.yml`에 갖고 있고 mysql-connector를 jar에 포함한다.
- Velocity에는 Bukkit API가 없다.

## 접근 방식 (선택: A)
- **A. Velocity 플러그인에 웹 내장 (선택)**: JDK 내장 `com.sun.net.httpserver.HttpServer`로 정적 파일 + JSON API 제공. 새 의존성·새 프로세스 없음, DB를 외부에 노출하지 않음, 프록시가 하나라 중복 실행 없음. 단점: 프록시가 꺼지면 같이 꺼짐.
- B. 집 서버에 별도 Node 앱: 플러그인 설정에 키를 둔다는 요구와 어긋나고 관리 대상이 늘어남.
- C. xmaslegacy.xyz에 /admin 추가: 오라클 API가 집 DB까지 터널을 뚫어야 해서 보안상 불리.

## 결정된 사항
- **키 파일**: `plugins/xmaslegacy-velocity/admin-keys.yml`
  ```yaml
  keys:
    - "긴-랜덤-문자열-1"
    - "긴-랜덤-문자열-2"
  ```
  서버에만 존재. 리포지토리에는 없고, 실수 방지로 `.gitignore`에 `admin-keys.yml` 추가.
  요청마다 파일 수정 시각을 확인해 바뀌었으면 다시 읽는다(재시작 불필요). 파일이 없거나 비어 있으면 웹 서버를 띄우지 않고 경고 로그.
- **인증**: 첫 화면에서 키 입력 → `POST /api/login` → 맞으면 랜덤 세션 토큰을 HttpOnly·SameSite=Strict 쿠키로 발급(12시간, 메모리 보관). 키 비교는 상수 시간 비교. 틀리면 IP당 분당 5회 제한. 이후 모든 `/api/*`는 세션 쿠키 필수(401).
- **포트/주소**: `config.yml`에 `admin-web: { enabled: true, port: 8095, bind: "0.0.0.0" }` 추가(기본값 동일).
- **읽기 전용**: 모든 쿼리는 SELECT만.
- **탭과 데이터**
  | 탭 | 테이블 | 표시 |
  | --- | --- | --- |
  | 개요 | 전체 | 유저 수, 총 달러, 대기 중 문의 수, 최근 문의 5개 |
  | 유저 | `users` | 표(이름·직업·레벨·달러·플레이타임·티어·숙련도), 검색·정렬, 클릭 시 상세 카드(칭호 목록, 각종 상태값, 해당 유저의 가방·문의·후원 바로가기) |
  | 문의 | `inquiry_logs` | 상태별 필터(PENDING/답변완료 등), 대화형 카드(질문 → 답변), 시간순 |
  | 가방 | `bags` | 유저 선택 → 54칸 인벤토리 그리드에 아이템 아이콘·개수, 마우스 올리면 이름·인챈트·로어 툴팁 |
  | 우편함 | `bag_mailbox` | 수령 대기 아이템 묶음, 가방과 같은 아이템 표시 |
  | 후원 | `products` | 받는 사람(이름으로 변환)·상품·지급 여부 |
  | 업적 | `Advancements`/`Players` | 플레이어별 달성 업적 목록 |
- **가방 아이템 해석**: DB 값은 Base64로 감싼 Bukkit YAML. 서버에서 Base64를 풀고 SnakeYAML로 맵으로 파싱해(Velocity 런타임에 없으면 jar에 포함) `{slot, id, count, name, lore, enchants}` JSON으로 내린다. 파싱 실패 항목은 원문 일부와 함께 "해석 불가"로 표시.
- **아이템 아이콘**: 외부 CDN 의존 없이, 아이템 ID 기반 색상 블록 + 짧은 이름 라벨. (실제 텍스처는 비목표)
- **UUID → 이름**: `users` 테이블로 변환, 없으면 UUID 앞 8자리.

## 프론트엔드
- 정적 파일(HTML/CSS/JS 한 세트)은 jar 리소스 `admin-web/`에 넣고 플러그인이 서빙. 빌드 도구 없이 바닐라 JS.
- 비주얼: xmaslegacy.xyz와 같은 결 — 짙은 남색 밤하늘 그라디언트, 은은하게 내리는 눈(캔버스, `prefers-reduced-motion`이면 끔), 마크 버튼 질감의 탭, 픽셀 폰트(Galmuri 계열, 웹폰트 1개), 빨강·금색 포인트.
- 1280px 데스크톱 우선, 모바일에서도 표가 가로 스크롤로 깨지지 않게.

## 빌더 재량
- 패키지 구조, 클래스 이름, 페이지네이션 크기, 정확한 색상값, 툴팁 모양.
- 개요 탭 지표 추가 여부.

## 검증
- 로컬: 단위 테스트로 키 검증(맞음/틀림/파일 변경 반영)과 아이템 YAML 파싱 확인.
- 서버: jar 배포 후 LAN에서 `http://192.168.45.51:8095` 접속, 키 없이 `/api/users`가 401인지 curl로 확인.
